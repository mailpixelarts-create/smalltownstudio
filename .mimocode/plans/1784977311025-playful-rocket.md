# Plan: Smooth Out Entire Site + Rebuild BTS Gallery

## Goal
Make every animation and interaction on the site feel buttery smooth — no jerks, no flicker, no jank. Two areas to fix:

1. **BTS Gallery** — complete rebuild (currently broken, only 3 images show)
2. **Featured Work + Site-wide smoothness** — polish all animations for silky feel

## Part 1: BTS Gallery Rebuild

### Problem
- `loading="lazy"` + `overflow: hidden` = images beyond first 3 never load
- GSAP ScrollTrigger per-item animation leaves off-screen items at `opacity: 0`
- `slideWidth` calculated once at init, breaks on resize
- 24 images but only 8 hardcoded dots

### Solution: Slide-based GSAP carousel

**`index.html`** (lines 294-340) — Replace entire BTS section:
- Group 24 images into 8 `.bts__slide` wrappers (3 images each)
- Add `.bts__viewport` wrapper with `overflow: hidden` around the track
- Remove all `loading="lazy"` from BTS images
- Remove hardcoded dots — JS will generate them dynamically

**`css/style.css`** (lines 860-973, 1159-1165) — Replace all `.bts__*` styles:
- `.bts__viewport` — `overflow: hidden` clipping mask
- `.bts__track` — `display: flex`, no overflow (viewport handles it)
- `.bts__slide` — `flex: 0 0 100%`, contains 3 items with gap
- `.bts__item` — `flex: 0 0 calc((100% - 2*gap)/3)`, aspect-ratio 4/3, GPU-accelerated
- Hover: `.bts__item:hover img` — `scale(1.08)` + remove grayscale filter, `transition: 0.6s cubic-bezier(0.25, 0.46, 0.45, 0.94)`
- Mobile (≤768px): 1 image per slide, hide arrows

**`js/main.ts`** — Replace `initBtsSlider()` (lines 468-528):
- Auto-generate dots from `.bts__slide` count
- `goToSlide(index)` uses `gsap.to(track, { x: -index * viewportWidth, duration: 0.8, ease: 'power3.inOut' })`
- Resize handler: recalc position on `window.resize`
- Replace old BTS scroll animation (lines 260-274) with section-level trigger

## Part 2: Featured Work + Site-wide Smoothness

### Problem
Animations feel jerky — likely caused by:
- Missing `will-change: transform` on animated elements (no GPU layer promotion)
- GSAP `gsap.from()` competing with CSS transitions on hover
- Film card entrance animation `delay: (i % 2) * 0.15` creates uneven timing

### Fixes

**`css/style.css`** — Add GPU acceleration to animated elements:

1. **Film card image** (line 634): Add `will-change: transform` to `.film-card__image img`
2. **Film card overlay** (line 645): Add `will-change: opacity` to `.film-card__overlay`
3. **Film card info** (line 670): Add `will-change: transform, opacity` to `.film-card__info`
4. **BTS items**: Already covered in Part 1 rebuild

**`js/main.ts`** — Smooth out GSAP animations:

1. **Film card entrance** (lines 229-242): Change easing from `power3.out` to `power4.out` for smoother deceleration. Change delay from `(i % 2) * 0.15` to `i * 0.1` for even stagger
2. **Awards items** (lines 245-258): Change duration from `0.6` to `0.8` for smoother feel, easing to `power3.out`
3. **Client logos** (lines 277-291): Change duration from `0.5` to `0.7`, easing to `power3.out`
4. **Section labels** (lines 135-147): Change duration from `0.8` to `1.0` for more graceful reveal

**`css/variables.css`** — No changes needed (easing curves already well-defined)
